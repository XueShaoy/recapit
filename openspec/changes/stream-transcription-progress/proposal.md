## Why

当前 CLI 在进入 Whisper 转写后只输出一次阶段名称，随后长时间没有可见反馈，用户无法判断任务仍在运行、已经处理到哪里或还需等待多久。长录音配合 `turbo` 等较大模型时，这种信息缺失尤其容易被误判为卡死。

## What Changes

- 在转写前显示录音时长、实际模型、设备、计算精度和预计耗时区间，并明确首次模型下载不计入推理估算。
- 在模型加载和转写期间持续显示活动状态、已耗时、音频处理位置、百分比、分段数量及动态剩余时间。
- 针对交互终端和非交互日志提供不同但语义一致的输出：终端原位刷新，日志定期输出新行，确保 Agent 命令面板持续可见。
- 提供可选的实时识别文字预览；默认不把录音内容写入终端日志。
- 记录本机同模型/设备/计算精度的历史处理速度，用于改进后续录音的转写前估算；没有历史数据时使用保守区间并标明估算来源。
- 保持最终转写、总结契约、时间码和检查点格式不变。

## Capabilities

### New Capabilities

- `transcription-progress`: 定义转写前耗时预估、运行中进度与动态 ETA、活动心跳、可选文字预览及终端输出行为。

### Modified Capabilities

无。

## Impact

- 影响 `src/recapit/transcribe.py` 的分段消费方式和进度事件接口。
- 影响 `src/recapit/workflow.py` 与 `src/recapit/cli.py` 的阶段反馈和终端渲染。
- 可能新增本地性能历史文件；该文件不属于转写业务产物，损坏或缺失不得阻止转写。
- 扩展 CLI 选项与自动化测试，不引入远程服务或 API Key。
