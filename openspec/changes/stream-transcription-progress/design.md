## Context

现有 `workflow.transcribe_recording` 通过字符串回调报告少量阶段状态；`FasterWhisperTranscriber._normalize_segments` 一次性消费 `faster-whisper` 的惰性分段生成器，在生成器结束前不会向上层暴露任何进展。长录音因此在“Whisper 本地转写”后保持静默。

`faster-whisper` 的分段包含原始音频时间范围，但启用 VAD 后，分段间的静音处理进度并不完全可见。CLI 同时运行在普通终端、Codex 命令面板和流水线日志中，输出策略必须兼顾原位刷新与可持久化日志。

## Goals / Non-Goals

**Goals:**

- 将转写阶段变成可观测、可测试的进度事件流。
- 在推理前给出有来源说明的耗时范围，并在运行中动态校准 ETA。
- 即使暂时没有新分段，也持续证明进程仍在工作。
- 默认不在终端日志暴露录音正文。

**Non-Goals:**

- 不承诺精确完成时间，也不把下载时间混入推理估算。
- 不改变 Whisper 解码参数、最终分段或产物 schema。
- 不实现网页界面、系统通知、暂停或断点续转 Whisper 推理。
- 不为了估时预先重复转写一段音频。

## Decisions

### 1. 使用结构化进度事件连接推理层与 CLI

新增与 UI 无关的进度事件，至少包含阶段、已处理音频秒数、总秒数、有效分段数、已耗时、可选 ETA 和可选最新文字。转写器在消费每个原始分段时立即规范化并发出事件，最终仍按开始时间排序后构造现有 `Transcription`。

工作流负责阶段事件，CLI 负责显示。测试替身可以直接断言事件序列，不依赖终端控制字符。

备选方案是直接启用 `faster-whisper` 的 `log_progress=True`。它能显示内部 `tqdm`，但无法统一模型加载心跳、转写前估算、隐私默认值和非 TTY 日志，也把第三方输出格式暴露成项目契约，因此不采用。

### 2. 进度使用单调的最远音频位置

每次收到分段后，以 `max(previous_position, clamp(segment.end, 0, duration))` 更新处理位置，百分比限制在 0% 到 99% 之间；只有生成器正常结束才发出 100% 完成事件。这样可以容忍异常乱序分段，并避免最后一段早于文件末尾时永远无法完成。

VAD 静音期间没有分段可用，因此进度可能短暂停顿。活动心跳仍更新时间和状态，避免误判卡死。相比侵入 `faster-whisper` 内部 seek 循环，这是更稳定的公共接口方案。

### 3. 将活动心跳与业务进度分开

CLI 在模型加载和转写任务外层维护轻量刷新器：交互终端定时重绘，非交互输出按最长 30 秒间隔发出心跳。进度事件只更新共享快照，不自行操作终端。

刷新器必须在成功、异常和键盘中断路径中关闭并恢复正常换行。它不写业务产物，也不改变转写错误传播。

### 4. 采用“历史优先、首轮区间、运行中校准”的 ETA

耗时使用实时率 RTF：`推理秒数 / 已处理音频秒数`。

- 转写前若存在相同机器指纹、模型、设备和计算精度的历史样本，使用最近成功样本的中位数，并按历史离散程度生成范围。
- 没有历史样本时，使用按模型量级和 CPU/GPU 类型维护的保守 RTF 区间；UI 明确标记为首次估算。
- 运行中只有在达到最小已用时间和最小已处理音频阈值后才显示 ETA，并对最近速度使用指数平滑，减少跳动。
- 模型下载和模型加载分别显示阶段耗时，不计入纯推理 RTF。

备选方案是启动前转写固定切片做基准测试。它会重复计算、延迟真正任务，还可能因切片静音而产生误导，因此不采用。

### 5. 性能历史使用尽力而为的用户缓存

历史文件放在平台用户缓存目录的 Recapit 命名空间，采用带版本的 JSON 和原子替换。每个运行配置只保留少量近期成功样本。记录仅包含硬件/运行配置摘要、音频时长、推理耗时和 RTF，不记录文件路径、文件名、哈希或转写内容。

读取、解析和写入失败均降级为无历史数据，不得改变转写结果或退出状态。

### 6. 默认只显示元数据，文字预览显式开启

CLI 增加 `--live-text/--no-live-text`，默认关闭。开启后，交互终端显示经过单行清理和长度截断的最新分段；非交互环境仅随节流后的进度行输出，避免为每个分段刷屏。完整文字仍只写入既有产物。

## Risks / Trade-offs

- [VAD 和长静音使分段结束时间不能代表内部精确 seek] → 使用单调进度、活动心跳和完成时强制 100%，并将 ETA 明确标为估算。
- [首次估算在未知硬件上偏差较大] → 展示范围与来源，运行后动态校准，成功记录用于后续本机估算。
- [动态终端控制符污染捕获日志] → 根据 TTY 自动选择原位刷新或节流的新行输出。
- [频繁刷新影响性能或输出过多] → UI 刷新与模型事件解耦，终端限制刷新频率，日志按时间和百分点节流。
- [性能历史带来额外状态] → 采用非内容、版本化、尽力而为的缓存，任何错误都不阻止转写。
- [实时文字可能泄露敏感内容到日志] → 默认关闭，只有用户显式启用才输出。

## Migration Plan

1. 增加进度事件和纯计算的估时组件，同时保持现有转写结果模型不变。
2. 将 `faster-whisper` 分段消费改为逐段规范化并发事件，保留最终排序和校验。
3. 在工作流中发出校验、模型加载、推理、写入和完成阶段事件。
4. 在 CLI 增加 TTY/非 TTY 渲染器及 `--live-text` 参数。
5. 增加可选性能历史；失败时验证可无损降级。
6. 使用短录音替身测试事件，再用真实长录音验证进度持续可见和 ETA 收敛。

回滚时可以移除 CLI 进度渲染并恢复字符串阶段回调；转写产物 schema 未变化，无需迁移已有文件。
